## 4. 当前阻塞与风险

### R1：复杂精确几何仍进入上下文计算图

当前 `build_common()` 仍对原始 GMBA 几何直接执行 `buffer(16000)`，并用于 DEM `filterBounds`、mosaic/clip 和 landform clip。`geometry(maxError=1000)` 不是显式几何简化。

风险：删除矢量边界环可能已经消除主要对象膨胀来源，但这仍只是合理推测，不能据此宣称历史错误已修复。

### R2：批次 `toList()` 依赖仍进入单山体任务

当前批次选择先通过 `ordered.toList(max_mountains, mountain_offset)` 构建集合，单山体任务随后从该集合过滤 ID。

风险：每个任务保留不必要的排序和批次选择子图；虽然不一定是主要错误来源，但会增加计算图依赖。

### R3：`maxSize=512` 的元数据描述过强

Earth Engine 会屏蔽宽或高超过 `maxSize` 的对象。当前算法利用这一行为把大对象视为“非小对象”，因此它不是 0.5 ha 科学阈值，但也不应描述成完全不影响语义的纯计算参数。

### R4：运行标识尚未完全统一

- `WORKLOAD_TAG` 仍含旧日期 `20260823`；
- 默认 run label 为 `mountain_v4_jrc_mmu`；
- 运行手册示例为 `gmba_v4_jrc_mmu`。

正式运行前应统一，以免 registry、任务列表和 Asset 审计混乱。

### R5：本地工作树不是安全的功能分支工作区

当前本地 `main` 落后远程并包含尚未提交的旧版修改。不得切换分支、重置或覆盖这些修改。后续实现应在保留现有工作树的前提下，使用新的干净 worktree 或由研究者确认的功能分支继续。

## 6. 验收标准

### 必须满足

- MMU 顺序、阈值边界、八邻域和 `pixelArea()` 未改变。
- 精确 GMBA 仍是正式研究域；上下文简化不裁掉正式域或邻域支持。
- 四个历史失败山体不再出现 `Object too large`，或已取得足够证据定位仍存在的具体算子。
- 30 m、1 km 和 QA 的波段、元数据、配置哈希一致。
- Zero Crossing 主结果和 Canny 敏感性结果的 run label 完全分离。
- 无 Asset 覆盖、旧哈希恢复或跨版本混写。

### 科学合理性抽查

- 填充面积仅来自 `<0.5 ha` 的八邻域非森林对象。
- 删除面积仅来自 `<=0.5 ha` 的八邻域森林对象。
- 填充不会在 QA 中形成明显的大型谷地、湖泊或开放地带。
- Otsu 阈值和候选样本量不存在异常退化。
- 最终树线主要位于合理高程带，低海拔森林外缘残留可被识别和报告。
